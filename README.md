# Quick Relist

A local-first Windows desktop workspace for preparing relisting jobs one listing at a time. This is an **early, non-operational development build**. It cannot yet capture a complete listing, remove, archive, recreate, or publish real Hub listings. Do not use it to relist property.

## Intended workflow

1. Enter one or more RXCU references and open the Hub session. Sign in and enter OTP yourself.
2. Capture the complete original listing and full-size media, verify the exact source and original portal choices, then review and approve the replacement address before any destructive operation.
3. Recheck the original; remove it from the selected portals and verify removal; archive it using “Listing has been cancelled” and “Mandate expired”.
4. Recreate the same sale or rental listing with the approved address and captured details and media. Compare the saved replacement with the original before publishing to the approved portals. Distinguish submission from confirmed publication.

## Available read-only preparation

- Open a separate Chrome session with a new private temporary profile and sign in yourself. The app disables browser password saving and does not use your existing Chrome profile. It deletes its temporary profile only after Chrome closes successfully; a crash or failed close can leave protected session files on the PC. Search for an RXCU and open its unique matching editor.
- **Capture matched editor tabs** reads the observed Listing particulars, Deal Particulars, Media and Portals tabs. It checks the source reference and browser identity around every accepted page, waits for stable rendered content, and keeps earlier guarded pages if you stop or navigation fails. It records the observed business-selector codes and media asset IDs, positions and original-source references. These are observations, not a verified complete source backup; unopened dialogs, related records, account ownership and full field fidelity remain unresolved.
- The matched capture also reads existing bedroom, bathroom, kitchen, parking and lounge option dialogs when their observed counts and controls are supported. Checkbox states and descriptions stay grouped by room. Each dialog is opened once, closed only with Escape, and accepted only after the listing reference and unchanged main fields are checked again. A failed or uncertain close stops navigation and keeps any unverified dialog data separate. Other room types and related records remain unqualified; Add, Done and remove controls are never used.
- Native tables retain actual row/cell membership, spans, header relationships and scoped action/chip labels alongside their plain-text rows. Irregular or unsupported structures remain marked. A global publication chip is never assigned to a portal or treated as proof of external publication. The five observed mandate/listing date pickers retain strictly bound raw input and Year/Month/Day observations without interpreting, changing or renewing dates; unsupported or conflicting layouts remain unresolved.
- **Save current page** can still preserve a manually selected page or an already-open dialog. **Prepare tentative address** makes a separate local draft without changing Hub or approving a relist.
- **Review copied listing fields** turns a matched observation into a searchable, read-only inventory of the observed particulars, dates, prices, selections, room counts, commissions and descriptions. Each value retains its original control and source location. Missing, conflicting and unmapped fields remain visible; older observations never fill a missing value silently. Country/property selection codes stay separate from their display labels, checkbox values keep their raw polarity, and suburb text is not treated as a verified selected suburb.
- **Compare with a saved replacement** keeps the selected original capture fixed and asks you to choose a different saved listing job and its exact capture. It compares observed listing fields and supported room options side by side, with original values, provenance, missing or unresolved coverage and observation chronology. This reads local records only: it does not create a replacement, approve differences or enable publication. Room alignment is positional; equal partial observations do not establish a complete copy.
- **Download photo pack** makes one request from the matched editor. When supported browser events match a completed ZIP to that frame and RXCU filename, its size and hash are checked and it is imported into the selected local job. Browser events cannot prove exact click causality. Unknown, ambiguous or unsupported outcomes remain unassigned for manual review; no download is automatically retried. Photo/floorplan classification, order, captions, cover, original resolution and completeness are not established by a ZIP or event match.
- After any automatic download attempt, further requests pause. Use **Review previous download** in the workspace or Connection & safety page. Check browser download history, then close every Quick Relist browser, including earlier sessions. Explicit review records a protected local receipt and preserves every file, including incomplete downloads. Resetting never retries, imports, attributes or verifies a pack. Reopen Hub and select the listing again for a new request.

The Hub connector and intended relisting workflow are **not complete**. Read-only collection and download behavior still require end-to-end qualification on the live Hub. The state machine is a development aid, not evidence of a verified relist. If an operation has an uncertain outcome, check Hub before trying again. Archiving and replacement are not atomic and cannot be automatically rolled back. No live listing change is enabled by these observations or tentative drafts.

The development mutation engine uses immutable commands, explicit expected revisions, non-mutating replacement validation, bound receipts and read-only reconciliation. Synthetic providers exercise removal, cancellation/archive, exact-source recreation and publication, including crashes and conflicts. **No qualified live provider is included or enabled.** The [provider contract](MUTATION_ADAPTER_CONTRACT.md) describes the integration evidence still needed. If a replacement requires new mandate dates, the workflow blocks rather than inventing or extending them.

A separate development component implements ordinary browser field interactions for the observed text, count, checkbox, radio, dropdown and segmented-date controls, with exact readback and stop-on-mismatch behavior. It runs only against a fresh nonce-bound localhost fixture; its public Hub entry point refuses before accessing the browser, and it is not connected to the desktop workflow. It does not create, save, upload, archive or publish. See the [field-transfer scope and qualification gaps](tests/HUB_FORM_WRITER.md). Browser field changes could autosave on a real service, so a successful synthetic readback establishes neither server persistence nor the absence of a server change.

The development creation coordinator also persists individual draft-allocation, field-copy and media-upload stages, with immutable commands, immediate draft-ID recovery and exact final comparison. An optional Engine API handles partial creation and explicit checkpoint-bound continuation without repeating allocation. Offline tests exercise the full synthetic workflow and interrupted stages through the actual SQLite coordinator. This remains separate from the desktop app and supplies no live Hub provider. See [staged creation and recovery](CREATION_RECOVERY.md) for behavior, storage requirements and qualification gaps.

Two further development components prepare exact [field-copy candidates from pinned captures](tests/TRANSFER_PLAN.md) and exercise [native media file selection](tests/HUB_MEDIA_WRITER.md) against a localhost upload fixture. The planner retains target baselines, provenance and unresolved coverage without creating a write request. The media fixture receives actual browser-selected bytes and hashes them, but the adapter is limited to an empty synthetic target and one selection per upload input. Shared-grid order, captions, cover and live persistence remain unqualified. Neither component is wired into the desktop app or a live provider.

A separate [media metadata and recovery component](tests/MEDIA_METADATA.md) exercises exact captions, explicit cover choice and global photo/floorplan order through ordinary controls in a localhost test application. Its private journal records each intention before interaction and reconciles interrupted stages without repeating them. Hub's cards advertise keyboard sorting, but the modeled caption/cover controls, saved-state receipts and revision guarantees are not verified Hub behavior. This component neither proves a complete media backup nor connects the upload and creation components into a working live workflow. The desktop launcher and its read-only behavior are unchanged.

The [integrated synthetic draft workflow](tests/DRAFT_PIPELINE.md) connects the field, upload and metadata handlers on one localhost service, one draft and one revision history. It copies selected supported text fields, applies an exact approved text-address projection, uploads actual generated image bytes, preserves supported metadata and compares the saved result. The metadata baseline comes from that service's completed upload state. It starts with an already-bound unpublished draft: allocation, complete source coverage, suburb selection, the desktop workflow and the real Hub provider remain outside its scope. See [live test readiness](LIVE_TEST_READINESS.md) for the concrete gates before an authorized real-listing pilot.

## Run locally

Requires Python 3.11+ and PySide6. From a virtual environment, install with `python -m pip install -e .` then run `python -m quick_relist`. For the read-only Chrome inspector, install `python -m pip install -e ".[browser]"`. For tests: `python -m pip install -e ".[test]"` then `python -m pytest`. Selenium may need a compatible Chrome and driver. Do not enter passwords or OTPs into this app; sign in directly in the browser.

Batch records are stored locally under the operating system’s per-user data directory (on Windows, `%LOCALAPPDATA%\QuickRelist`). They are not encrypted by this app. Limit access to the PC and use appropriate disk protection. Saved partial observations, tentative address drafts and imported media are stored there too and can contain sensitive property or personal information. They are not a complete source backup.

All tests must use synthetic data. Do not test destructive actions against a real listing without specific permission. Never commit real listing records, images, screenshots, credentials, OTPs, browser profiles, local databases, or logs. Local data may include private property information and should be protected and backed up by the operator.

For a controlled preparation check, follow the [Windows read-only test plan](READ_ONLY_TEST_PLAN.md). Successful steps do not qualify live relisting.

## Before a release

Implement and validate the real connector against current Hub screens; verify all source fields, nested dialogs and full-size media, address edits, portal synchronization, safe interruption and uncertain outcome reconciliation. Test a controlled sale and rental end-to-end only with explicit permission for the particular listings. Validate the Windows installer, signed distribution and dependency licensing, including Qt obligations. No installer or releases are currently provided.
